# ALFA-Proven Lessons

Only lessons verified against this repository's code and READMEs (Round 1 tag `round-1-complete`, Round 2 tag
`round-2-complete`, Flagship 01 tag `flagship01-final`, Experiment 02 at `src/exp02/`, Experiment 03 tag `exp03-final`). Everything here is `[ALFA-PROVEN]`
**within these limits**: every verification ran in software GL (SwiftShader) in headless Chromium. **No real-GPU frame rate
has ever been measured.** The only physical-device evidence is one phone rendering check (Exp 03, AL23). Where a "lesson" is only a decision that was never measured, it is marked *(decision, unmeasured)*.

Human verdicts so far: R1 "an effect between two images". Flagship 01: technical PASS, premium art direction PARTIAL, human wow NOT
achieved. Exp 02: awaiting review. Exp 03: concept proven, premium motion PASS, human WOW NO (`docs/experiments/EXP03_THE_UNBUILT.md`). So none of these lessons proves anything *looks* premium. They prove what *works technically*.

| # | Lesson | Evidence |
|---|---|---|
| AL1 | **Make every visual state a pure function of scroll progress.** Native scroll → normalized progress → SmoothDamp → pose. Reverse, pause, jump, reload and resize then work without any special handling. No timeline library is needed. | All four experiments. `src/scroll.ts` (critically damped SmoothDamp). Robustness scripts: slow/fast/reverse/flick/reload/resize PASS (`scripts/robustness.mjs`, `scripts/robust02.mjs`). |
| AL2 | **Give each mass its own inertia.** Several SmoothDamps with different `smoothTime` (heavy 0.8 s, light 0.36 s) read as mass and overlap without any physics engine. | Flagship `src/main.ts` (5 dampers), Exp02 `src/exp02/main.ts` (3 inertia groups). |
| AL3 | **Clamp `dt`** (default 0.05 s) so a tab switch or a slow frame can't make the smoothing jump. Snap the dampers on `pageshow` (bfcache restore). | `src/exp02/main.ts` L65–70, L55. |
| AL4 | **Render on change.** Build a key from the quantised animated values plus the viewport size, and render only when it changes. A still page then costs no GPU. | `src/exp02/main.ts` L74–76. Only valid when nothing animates on time alone. Flagship renders every frame because of its ambient drift. |
| AL5 | **Adaptive render scale on sustained slow frames, not single spikes.** Accumulate slow time (dt > 1/24 s), drop the scale by 0.1 to a floor of 0.5, and recover slowly. Cap DPR (1.75 desktop). | `src/main.ts` L64–70, `src/flagship/engine.ts` (`maxDpr`, `setScale`). *Thresholds untuned on real GPUs.* |
| AL6 | **Fallback is a designed poster, not an error.** No WebGL2 / context lost / `?fallback=1` → a static composition built from the same concept (Exp02 draws the printed survey sheet), and all copy still works. | `src/exp02/main.ts` L22–39 (`webglcontextlost` → fallback). R2 also checks for float render targets. |
| AL7 | **Correct the material first, then post.** Post is seasoning. Bloom was kept tiny (0.06 strength) and grain/vignette subtle, and a `?raw` switch disables post for honest look-dev. Exp02 ships with *no* post chain (Neutral tone mapping only). | `src/flagship/engine.ts` (bloom 0.06, grain 0.012, `setRaw`), `src/exp02/scene.ts` L163. |
| AL8 | **An authored environment beats a generic HDRI for controlled premium objects.** Flagship bakes a dark studio (broad softboxes for form, thin strips for edges) through PMREM once. | `src/flagship/env.ts`. |
| AL9 | **Analytic shading tricks in a shared GLSL patch** (ray/AABB occlusion, sampled line light, rectangle mirror of the slot) gave controllable light where shadow maps or real area-light shadows would be costly or unavailable. | `src/flagship/shading.ts`. (three.js `RectAreaLight` has no shadows, S1 `src/lights/RectAreaLight.js`.) |
| AL10 | **Ancestry through one shared source.** Derive both states from one authored source (Exp02: one height field → printed contours *and* leaf geometry; R2: the circle keeps centre and radius across every hand-off). The transformation then reads as causal, not as a dissolve. | Exp02 README table, `src/exp02/terrain.ts`. R2 README "The circle never leaves". |
| AL11 | **Shader distortion without a physical cause looks like a demo.** Reflection-distortion ripples on the lake aliased and read as a "shader demo", so they were replaced by still water plus a faint brightness swell. | Exp02 README "What failed / was replaced". |
| AL12 | **Particles/shards carrying real image colour still read as "an effect between two images".** Round 1 (130k instanced shards, tonal optimal-transport pairing) was technically strong and failed creatively. Round 2 deliberately used no particles. | R1 README + human verdict. R2 README "none is particles". |
| AL13 | **Separate plates for things that must hand over.** Printed water lining under real water looked jaggy, so a separate plate fades out. The printed relief shading sits on its own plate so it can hand over to real cast shadow. | Exp02 README, `src/exp02/print.ts` L161. |
| AL14 | **Light changes must not compete with geometric motion.** When the light change overlapped the leaf rise (62–69%) it muddied both. Start the light change after the geometry has landed. | Exp02 README. |
| AL15 | **Side/grazing light shows material thickness, contre-jour muddies it.** Exp02 switched from contre-jour to a west side light so the paper walls read as paper. | Exp02 README. |
| AL16 | **Portrait needs its own cinematography, not shrinking.** Widen the vertical FOV or use a lens shift to keep the framing, re-centre, and set different type placement per orientation. Unsolved: landscape-shaped objects leave empty bands in portrait. | `src/flagship/engine.ts` resize (portrait FOV), Exp02 README "Unresolved". R1 found a portrait letterbox bug only by testing 390×844. |
| AL17 | **Inspect the worst frame, not the hero frame.** Labelled progress contact sheets (`scripts/strip.mjs`, 1/16 steps) plus seam checks at every transition boundary found the NaN from `exp` overflow, ray-march zippers, bright washes and SDF jaggies. | R2 README R2-5, `scripts/strip.mjs`, `scripts/seq.mjs`. |
| AL18 | **Check GPU memory stays constant across resize cycles.** Texture/geometry counts from `renderer.info.memory` must not grow. | R1/R2 robustness (7 resize cycles, no growth). Exp02 exposes `info()`. |
| AL19 | **Software GL hides perf problems and also exaggerates them.** SwiftShader is fine for correctness, framing and seams, and is useless for frame-rate judgement (`?dtmax` exists so slow rigs settle). Every perf claim stays unproven until it's measured on a real GPU. | All READMEs, "Known limitations". |
| AL20 | **Text as SDF is a geometry source for morphs.** Rasterise the glyphs, run an EDT to get a half-float SDF texture, and the circle → word morph works. Serif tips soften at 1024×512. | R2 `src/gl/textsdf.ts` (tag `round-2-complete`). |
| AL21 | **Large shadow maps were chosen without measurement** *(decision, unmeasured)*. Exp02 uses 4096² desktop / 2048² mobile PCF. A candidate for the first real-GPU measurement. | `src/exp02/scene.ts` L299. |
| AL22 | **A planar `Reflector` at reduced resolution is enough for still water and a floor mirror.** Flagship 768², Exp02 0.7 × capped-DPR viewport. A full-resolution mirror was never needed. | `src/flagship/world.ts` L129, `src/exp02/scene.ts` L251–253. |
| AL23 | **Never LINEAR-sample float32 render targets unless `OES_texture_float_linear` is present; use NEAREST for 1:1 full-screen passes.** Most phone GPUs lack the extension; a linearly filtered float32 target is then incomplete and samples black: UI visible, scene black, no error. SwiftShader and desktop GPUs hide it. Detecting `EXT_color_buffer_float` alone is not enough. | Exp03 on a physical Android phone (Chrome: black scene). Reproduced in SwiftShader by withholding only that extension; fixed with NEAREST accumulation targets (`src/exp03/scene.ts`, commit `10a0145`), human-verified on a physical phone (Brave). Desktop output changed by ≤1/255 on 0.01 % of pixels. `?diag` device report: `src/exp03/diag.ts`. |
| AL24 | **Grow structure over a rigid parametrisation, not by scaling meshes.** Building the final geometry once and narrowing it per rigid isoline of a developable folding map gives exact intermediate geometry (nothing scales from zero, nothing pops) and stays a pure function of progress. Zero-extent ungrown matter must be fully degenerate (width *and* thickness), or it rasterises as slivers. | `src/exp03/motion.ts` (`growPlate`, `grow()`), Exp03 README *Motion Proof*. Software GL only. |
